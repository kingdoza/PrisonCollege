## 사용 규칙

이 문서는 최초 요구사항만으로 결정할 수 없는 게임 정책을 모은다.

- 결정 우선순위는 `사용자가 작성한 P/T 결정값 > 최초 요구사항 R > 기술 제안`이다.
- `결정값`이 비어 있는 항목은 코드에 임의로 반영하지 않는다.
- 선택지는 가능한 방향을 구분하기 위한 예시이며, 어느 것도 확정안이 아니다.
- 최초 요구사항에 이미 명시된 내용은 다시 선택하지 않고 “확정된 요구사항”에 기록한다.
- 기술 구현 방식도 팀 승인이 필요한 경우 `T` 항목으로 분리한다.

## A. 전체 진행 정책

### P-01. 튜토리얼 진입 방식

결정이 필요한 내용:

- 최초 실행 시 자동 진입인지, 메인 메뉴 버튼으로만 진입하는지
- 최초 실행 안내 팝업이 필요한지
- 전체 튜토리얼 건너뛰기 기능이 필요한지

결정값: 메인 메뉴 버튼으로만 진입

### P-02. 완료 및 재연수 저장 정책

결정이 필요한 내용:

- 완료 여부를 저장하는지
- 8단계 건너뛰기로 9단계에 도달한 경우 완료로 저장하는지
- 재연수 시 완료 기록을 유지하는지
- 게임을 종료했다가 다시 켰을 때 중간 단계부터 재개하는지

결정값: 완료 상태를 저장한다. 8단계를 건너뛰어도 완료로 판정한다. 재연수 시 완료 기록을 유지한다. 단계별 진행 상태는 저장하지 않으며, 튜토리얼 도중 종료한 뒤 다시 진입하면 처음부터 시작한다.

### P-03. 단계 번호

현재 구성은 3 다음에 5-1이 나온다.

선택할 내용:

- 현재 표시 번호 유지
- 5-1/5-2를 4-1/4-2로 변경
- 화면에는 번호를 표시하지 않음

결정값: 5-1/5-2를 4-1/4-2로 변경

### P-04. 안내 패널과 게임 정지

결정이 필요한 내용:

- 각 단계 안내가 자동으로 사라지는지, 별도 확인 입력이 필요한지
- 안내를 읽는 동안 플레이어 이동·시점·공격과 게임 시간을 멈추는지
- 단계 완료 문구의 표시 시간과 다음 단계 전환 방식

결정값: 안내 UI는 별도 확인 입력 없이 단계가 진행되는 동안 계속 표시한다. 목표 조건이 만족되면 해당 단계 UI의 제목, 부제목, 안내, 목표 조건을 한 번에 숨기고 다음 단계로 전환한다. 단계 UI 때문에 게임이나 플레이어 입력을 정지하지 않는다. 별도의 완료 문구 유지 시간은 두지 않는다.

### P-05. 단계별 입력 제한

최초 요구사항은 조작을 소개하는 순서만 있고, 소개 전 입력을 막을지는 명시하지 않았다.

결정이 필요한 내용:

- 0단계에서 Tab 이외의 이동/공격/F 입력 허용 여부
- 1단계에서 공격/F/장비 교체 허용 여부
- 2단계에서 공격과 장비 교체 허용 여부
- 아직 소개하지 않은 기능을 사용했을 때 무시, 허용, 안내 중 어느 처리를 할지

결정값: 아직 소개하지 않은 기능을 포함해 모든 입력을 허용한다. 단계별로 차단되는 기능은 없다.

## B. 이동과 탈출구

### P-06. 이동 마커 위치와 형태

결정이 필요한 내용:

- 실제 씬의 목표 위치
- 월드 아이콘, 바닥 원, 빛기둥 등 표시 형태
- 도착 판정 반경

결정값: 마커 오브젝트를 씬에 배치할거임. 도착 판정도 해당 오브젝트에서 독립적으로 판정해야함. 튜토리얼 관리 코드에서 해당 오브젝트를 참조.

### P-07. 봉쇄 대상 탈출구

결정이 필요한 내용:

- 튜토리얼 씬의 정확한 문/창문 목록과 `n`
- 모든 문/창문을 대상으로 할지, 지정된 일부만 대상으로 할지
- 단계 시작 시 모든 대상의 바리케이드가 없는 상태인지
- 2단계 완료 상태를 이후 단계와 8단계까지 유지할지
- 설치가 끝난 탈출구의 빨간 점멸을 즉시 끌지, 단계 완료까지 유지할지

결정값: 모든 문/창문을 대상으로 한다. 튜토리얼 씬 최초 진입 시 모든 대상의 바리케이드는 없는 상태다. 2단계 진입 시 상태를 다시 초기화하지 않으며, 플레이어가 이전 단계에서 미리 봉쇄했다면 해당 설치도 진행도에 포함한다. 2단계 완료 상태는 이후 단계와 8단계까지 유지한다. 탈출구의 빨간 점멸은 2단계가 완료될 때까지 유지한다.

추가작업 변경 결정: 탈출구 점멸은 메인 스테이지와 동일한 기존 `OutlineFader`의 주기적 fade in/out을 재사용한다. 정규 준비 시간 자동 실행과 `StageStartEvent` 종료 흐름은 보존한다. 튜토리얼에서는 관리 코드가 명시적으로 전달받은 대상 루트의 하위에서 비활성 오브젝트를 포함해 `OutlineFader`를 수집하고 공개 API로 점멸 시작과 종료를 제어한다. 이 방식은 런타임에 생성된 창문 파츠와 향후 탈출구 외 오브젝트에도 사용하며, 씬 전체 검색이나 매 프레임 polling은 하지 않는다.

### P-08. 설치 후 파괴 시 목표 카운트

최초 요구사항에는 “파괴되면 다시 설치”라고 적혀 있지만, 2단계 진행 중 파괴 상황을 실제로 만들지는 명시하지 않았다.

결정이 필요한 내용:

- 2단계는 학생이 없어 파괴가 발생하지 않게 할지
- 파괴가 발생하면 현재 설치 수가 감소하는지, 누적 설치 완료로 유지하는지

결정값: DB의 모든 학생은 대기 공간에 보이는 상태로 존재하지만 2단계에는 활성 행동 학생이 없다. 학생들은 Idle 자세를 유지하며 자율 AI, 이동, 공격, 피격과 부스터 효과가 차단되므로 바리케이드를 파괴하지 않는다.

## C. 위험 행동 구분과 대응

### P-09. 네 개의 정상/위험 행동 조합

원문에는 “아래의 정상 행동 학생과 위험 행동 학생”이라고 되어 있으나 실제 행동 목록이 포함되지 않았다. 네 문제의 내용을 각각 확정해야 한다.

| 문제 | 정상 행동 | 위험 행동 | 배치 장소 | 결정 상태 |
|---|---|---|---|---|
| 1 | 숭배 | 탈출구 공격 | 기존 `StageSpots` 행동 지점 | 결정 |
| 2 | 게임 | 해킹 | 기존 `StageSpots` 행동 지점 | 결정 |
| 3 | 정상 노래 | 저질 노래 | 기존 `StageSpots` 행동 지점 | 결정 |
| 4 | 춤 | 흡연 | 기존 `StageSpots` 행동 지점 | 결정 |

추가작업 답변: 메인 스테이지의 `StageSpots`와 `BehaveSpot` 점유 방식을 재사용한다. 랜덤 spot 선택 대신 튜토리얼 씬에서 각 학생이 사용할 행동 지점을 Inspector에서 직접 연결한다.

### P-10. 학생 배치 수와 순서의 정확한 의미

“정상 행동 학생과 위험 행동 학생을 두 명씩 순차적으로 배치”는 다음 중 어느 의미인지 확정이 필요하다.

- 문제마다 정상 1명 + 위험 1명, 2명씩 네 번
- 정상 학생 2명 + 위험 학생 2명, 총 4명을 순차 배치
- 각 행동 종류마다 정상 2명 + 위험 2명
- 별도 구성

결정값: 최초의 “두 명씩 순차 배치” 설명은 사용하지 않는다. 3단계 진입 시 DB 전체 학생 9명 중 8명을 무작위로 선택하고, P-09의 정상 역할 4명과 위험 역할 4명을 배정한다. 선택된 8명은 대기 공간에서 연수 이동 지점으로 순간이동한 뒤 각 행동 지점까지 달려간다. 선택되지 않은 1명은 대기 공간에 남는다.

### P-11. 위험 행동별 올바른 저지 방법

각 위험 행동마다 무엇을 하면 “저지 1회”로 인정할지 정해야 한다. 공격 적중, 완전한 쓰러뜨림, 특정 시설 F 상호작용, 바리케이드 유지 등은 서로 다른 조건이다.

| 문제 | 인정되는 저지 행동 | 인정 시점 | 공격 이외 해결 필요 여부 | 결정 상태 |
|---|---|---|---|---|
| 1 | 위험 행동 학생 공격 | 체력 0 도달 | 없음 | 결정 |
| 2 | 위험 행동 학생 공격 | 체력 0 도달 | 없음 | 결정 |
| 3 | 위험 행동 학생 공격 | 체력 0 도달 | 없음 | 결정 |
| 4 | 위험 행동 학생 공격 | 체력 0 도달 | 없음 | 결정 |

결정값: 저지 1회는 위험 행동인 학생 때려눕혔을때(체력 0) 만족

### P-12. 정상 행동 학생을 잘못 공격한 경우

결정이 필요한 내용:

- 학생이 실제 피해를 받는지
- 혼잡도가 증가하는지
- 현재 문제를 초기화하는지
- 목표 진행도를 감소시키는지
- 단순 경고만 표시하고 계속하는지
- 정상 학생을 쓰러뜨린 경우 복구/재스폰 방식

결정값: 정상 행동 학생도 실제 피해를 받는다. 최신 `P-47`에 따라 플레이어가 정상 학생을 체력 0으로 만들면 정규 `InnocentDown` 혼잡도와 경고를 적용한다. 문제나 단계 진행도를 초기화하거나 감소시키지는 않는다. 체력 0이 된 정상 학생은 3-1이 진행되는 동안 복구하거나 재스폰하지 않는다. 3-1이 끝난 뒤에는 메인 스테이지 자동 기상을 다시 허용하고 대기 공간 복귀를 시작한다.

### P-13. 위험 행동 유지와 시간 초과

결정이 필요한 내용:

- 플레이어가 저지할 때까지 행동을 무한 유지하는지
- 시설 사고처럼 결과가 발생하는 행동은 사고 직전에 멈춰 기다리는지, 사고를 반복하는지
- 일정 시간 미해결 시 힌트, 자동 재시작, 자동 해결 중 무엇을 할지

결정값: 모든 학생은 단계가 끝날 때까지 지정된 행동을 유지한다. 위험 학생은 체력 0으로 저지될 때까지 위험 행동을 반복한다. 탈출구 공격은 연출만 수행하며 실제 바리케이드 피해나 탈출을 발생시키지 않는다. 해킹도 연출만 수행하며 실제 조명 OFF를 발생시키지 않는다. 3-1 동안 학생의 공격력은 0이다. 저질 노래와 흡연 등 행동 기반 혼잡도 증가는 차단하되, 최신 `P-47`의 정상 학생 `InnocentDown` 혼잡도는 허용한다.

### P-14. 튜토리얼 전용 위험 표식

최초의 표식 없음 결정은 아래 최신 사용자 결정으로 대체한다.

결정이 필요한 내용:

- 표식의 모양, 색, 외곽선 사용 여부
- 위험 행동 시작 전부터 표시하는지, 실제 위험 구간부터 표시하는지
- 네 문제 모두 표시하는지, 첫 문제나 오답 후에만 표시하는지
- 정상 학생과의 구분을 표식 자체로 알려 줘도 되는지
- 8단계 미니웨이브에서도 표시하는지

결정값: 3단계에서는 위험 행동 학생 4명에게만 공용 목표 마커를 표시한다. 학생별 연수 이동이 끝나 행동 지점에 도착한 직후 표시하고, 해당 학생의 체력이 0이 되어 저지 진행도에 반영되는 순간 제거한다. 정상 행동 학생에게는 표시하지 않는다. 별도 `TutorialDangerMarker` 타입을 만들지 않고 1단계 위치 표시와 동일한 목표 마커 prefab을 사용하되 학생 표시용 높이와 스케일을 별도로 적용한다. 8단계 미니웨이브에는 위험 표식을 사용하지 않는다.

### P-15. 3단계의 혼잡도와 총기 사용

다른 혼잡도 발생을 제한한다고 했지만, 플레이어가 총을 쏘거나 정상 학생을 쓰러뜨린 경우까지 제한할지는 명시되지 않았다.

결정이 필요한 내용:

- 총기 발사 혼잡도 적용 여부
- 정상 학생 처치 혼잡도 적용 여부
- 3단계 종료 시 발생한 혼잡도를 유지할지, 다음 단계에서 어차피 0으로 초기화하므로 표시만 할지

결정값: 최신 `P-47`에 따라 3-1에서는 정상 행동 학생을 플레이어가 체력 0으로 만든 `InnocentDown` 혼잡도와 기존 경고만 허용한다. 총기 발사, 저질 노래, 흡연과 그 밖의 혼잡도 원인은 계속 차단한다. 발생한 혼잡도는 3-1 종료 때 임의 초기화하지 않으며 이후 명시적 초기화 단계까지 유지한다.

## E. 학생·교수 작업

### P-21. 6단계 시작 장비와 부스터 수량

결정이 필요한 내용:

- 시작부터 연수용 부스터를 장착할지, 플레이어가 장비를 교체해야 하는지
- 초기 탄약 수
- 자판기 보충량, 비용, 횟수 제한
- 빗나간 부스터를 회수할 수 있는지

결정값: 6단계 시작 시 연수용 부스터를 빈 장비 슬롯에 지급하고 탄약을 해당 장비의 최대치로 채운다. 지급 직후 부스터 슬롯을 자동으로 선택한다. 자판기의 보충량, 비용과 횟수 제한은 메인 스테이지 정책을 그대로 사용한다. 메인 스테이지와 동일하게 빗나간 부스터를 회수하는 시스템은 두지 않는다.

### P-22. 연수용 부스터 확률과 보정치 관계

작업 100%/광분 0%와 패시브 보정치 처리 방식을 아래처럼 확정한다.

선택할 내용:

- 연수용 부스터는 모든 패시브 보정을 무시하고 항상 작업
- 정규 계산을 거친 뒤 최종 확률을 100%/0%로 강제
- 튜토리얼에서는 패시브 아이템 자체를 비활성화

결정값: 연수용 부스터는 작업/광분 확률에 패시브 보정을 적용하지 않고 항상 작업 100%/광분 0%를 사용한다. 투척 속도, 공격 동작 등 확률 이외의 무기 수치는 본편 부스터와 동일하게 사용한다.

### P-23. 6단계 프로젝트 시작값과 종료 상태

결정이 필요한 내용:

- 6단계 진입 시 프로젝트 게이지를 0으로 초기화하는지
- 이전 단계의 프로젝트 상태가 있다면 유지하는지
- 조건 확인 후 작업 학생이 계속 일하는지, 작업을 중단하는지
- 6단계에서 프로젝트가 완성될 수 있는지

결정값: 6단계 진입 시 프로젝트 게이지를 0으로 초기화한다. 학생이 작업을 시작한 뒤 Inspector에 노출된 `n`초가 지나면 단계를 성공 처리하고, 단계 달성과 동시에 해당 학생의 작업을 중단한다. `n`의 실제 값은 Unity Editor에서 설정한다. `n`초 전에 작업 상태가 끊기면 타이머를 0으로 초기화한다. 프로젝트가 `n`초보다 먼저 완성되는 것은 허용한다. 이 결정이 최초 요구사항 R-10의 프로젝트 게이지 실제 상승 조건보다 우선한다.

### P-24. 7단계 프로젝트 상태

결정이 필요한 내용:

- 6단계의 프로젝트 진행도를 이어받는지, 0으로 초기화하는지
- 6단계 작업 학생의 기여를 유지하는지
- “교수 작업 상태로 완성”이면 학생이 함께 기여해도 인정하는지
- 교수 기여만으로 완성해야 하는지

결정값: 7단계 진입 시 프로젝트 진행도를 0으로 초기화한다. `P-23`에 따라 6단계에서 작업하던 학생의 작업은 6단계 달성과 동시에 중단된 상태로 진입한다. 7단계 동안 학생의 부스터 수용을 차단하며, 학생을 어떤 방법으로도 작업 상태로 만들 수 없다. 따라서 프로젝트는 교수 기여만으로 완성한다. 부스터 사용 입력 자체는 가능하지만 학생에게 작업 효과가 적용되지 않는다.

### P-25. 튜토리얼 프로젝트 보상

결정이 필요한 내용:

- 7단계와 8단계 프로젝트 완성 자금을 실제 인벤토리에 지급하는지
- 튜토리얼 화면에만 가상 자금으로 표시하는지
- 재연수 시 반복 획득이 가능한지
- 튜토리얼 종료 후 정규 스테이지 준비 자금으로 가져가는지

결정값: 프로젝트 보상을 정규 준비 자금이나 `InventorySystem`에 지급하지 않는다. 튜토리얼 세션 내부 수치로만 계산해 메인 스테이지와 동일한 형태의 HUD에 표시하며, 튜토리얼 종료 후에는 유지하지 않는다.

## F. 미니웨이브

### P-27. 미니웨이브 시작 탈출구 상태

- 일부를 파괴/손상 상태로 시작하는지
- 재시작할 때 어떤 상태로 돌아가는지

결정값: 최초 8단계 진입 시 2단계에서 설치한 탈출구의 현재 상태를 그대로 이어받는다. 8단계를 재시작하면 탈출구뿐 아니라 모든 튜토리얼 상태를 최초 8단계 진입 당시 상태로 복원한다. 구체적인 복원 항목은 `P-32`에 기록한다.

### P-28. 미니웨이브 장비와 보충 시설

결정이 필요한 내용:

- 고정 장비 목록과 슬롯 순서
- 각 장비 시작 탄약
- 부스터/총기 보충 시설 사용 가능 여부와 비용
- 플레이어가 정규 인벤토리 장비를 가져올 수 있는지

결정값: 장비의 공격·탄약·보충 동작은 메인 스테이지와 동일하게 사용한다. 정규 인벤토리 장비는 가져오지 않는다. 튜토리얼 전용 고정 로드아웃을 Inspector에서 직접 설정한다.

남은 에디터 설정: 고정 장비 목록과 슬롯 순서, 각 장비 초기 탄약, 사용할 보충 시설과 비용.

### P-29. 미니웨이브 학생 행동 범위

결정이 필요한 내용:

- 3단계에서 학습한 위험 행동만 나오는지
- 정규 1~4웨이브 행동 중 어느 범위가 나오는지
- 자발적 작업 확률
- 위험 행동을 동시에 몇 명까지 수행할 수 있는지
- 학생 스폰 위치와 로스터를 고정할지 무작위로 할지

결정값: 메인 웨이브와 동일한 행동 가중치 시스템을 사용하되, 튜토리얼 미니웨이브 전용 `BehaviorWeightSet` ScriptableObject를 Inspector에서 직접 연결한다. 위험 행동 동시 수행 인원에는 별도 제한을 두지 않는다. 최초에 생성해 둔 DB 전체 학생 9명 중 미니웨이브 설정 인원 `n`명을 무작위로 선택하고 연수와 동일한 출발용 이동 가능 지점으로 순간이동시킨 뒤 즉시 웨이브 행동을 시작한다. 기존의 “메인 스테이지 스폰 위치로 이동” 문구는 이 결정으로 폐기한다. 선택되지 않은 학생은 대기 공간에서 응원 자세를 유지하며 미니웨이브 행동과 집계에 참여하지 않는다.

남은 에디터 설정: 실제 사용할 asset과 행동별 가중치.

### P-30. 실패 후 재시작과 건너뛰기 UI

재시작 또는 건너뛰기가 필요하다는 사실만 확정돼 있다.

결정이 필요한 내용:

- 실패 화면에 두 버튼을 모두 즉시 표시할지
- 건너뛰기 확인 팝업 여부
- 건너뛰기 시 9단계로 이동하는지, 메인 메뉴로 이동하는지
- 건너뛰기가 완료 기록과 보상에 미치는 영향

결정값: 실패 화면에 `8단계 다시 시작`과 `건너뛰기` 버튼을 즉시 표시한다. 건너뛰기를 선택하면 별도 확인 팝업 없이 즉시 9단계로 이동하며 `P-02`에 따라 완료로 판정한다.

### P-31. 플레이어 사망과 낙하

결정이 필요한 내용:

- 0~7단계에서 플레이어가 사망 가능한지
- 8단계에서 사망이 즉시 실패인지, 정규 부활 흐름인지
- 낙하 시 현재 위치 복귀인지 체크포인트 재시작인지

결정값: 0~7단계에서는 플레이어 사망을 허용하지 않는다. 8단계에서 사망하면 정규 부활 흐름을 사용한다. 낙하 시 메인 스테이지와 동일하게 지정 위치로 텔레포트한다.

### P-33. 체크포인트 사용 위치

- 일시정지 메뉴에 `현재 단계 다시 시작`을 항상 제공할지
- 실패 가능한 8단계에서만 체크포인트 재시작을 제공할지
- 비정상 상태 감지 시 자동 재시작을 허용할지

결정값: 8단계 실패 화면에서만 `8단계 다시 시작`을 제공한다. ESC를 눌렀을 때 표시되는 메인 스테이지와 동일한 일시정지 메뉴의 재시작은 현재 단계가 아니라 튜토리얼 전체를 0단계부터 다시 시작한다. 비정상 상태 감지와 이에 따른 자동 복구·자동 재시작 기능은 두지 않는다. 학생 행동 런타임 준비는 `T-06`의 시작 전 1회 명시적 초기화 계약을 따른다.

### P-36. DB 학생 풀과 대기 공간 연출

결정값:

- 튜토리얼 씬 시작 시 `StudentDB`에 등록된 모든 학생을 한 번 생성하고 각 학생의 고정 대기 슬롯을 연결한다. 현재 DB 기준 인원은 9명이다.
- 0단계에는 전원을 일렬로 배치하고 충성 자세를 고정한다. 자율 AI와 이동은 비활성화한다.
- 1단계에도 전원이 충성 자세를 유지한다.
- 2단계부터 비연수 학생은 대기 공간에서 Idle 자세를 유지한다.
- 충성·대기·응원 상태 학생에게 공격과 부스터 효과를 적용하지 않는다. 자율 행동, 탈출, 작업, 혼잡도 원인과 단계/HUD 학생 집계에서도 제외한다.
- 학생이 연수를 시작하면 대기 슬롯에서 연수용 이동 가능 지점으로 순간이동한 뒤 지정 연수 지점까지 달려간다.
- 연수가 끝나면 대기 공간과 가까운 복귀용 이동 가능 지점까지 달려간 뒤 원래 대기 슬롯으로 순간이동한다.
- 연수 지점으로 이동 중이거나 대기 공간으로 복귀 중인 학생에게 공격과 부스터 효과를 적용하지 않는다.
- 학생 복귀 완료를 기다리지 않고 다음 단계로 즉시 전환한다. 복귀는 배경에서 계속 진행한다.
- 3단계 종료 시 쓰러진 학생은 단계 종료 후 메인 스테이지 자동 기상을 허용하고, 기상 완료 후 위 복귀 흐름을 따른다.
- 4-1은 3단계에 선택되지 않았던 1명을 사용한다. 완료 후 배경에서 대기 공간으로 복귀한다.
- 6단계는 4-1에 참여하지 않았고 대기 공간 복귀가 완료돼 `Standby` 상태인 학생 중 1명을 사용한다. 완료 후 배경에서 대기 공간으로 복귀한다.
- 8단계는 전체 학생 중 설정 인원 `n`명을 무작위로 선택해 연수 출발용 이동 가능 지점으로 순간이동시킨 직후 웨이브 행동을 시작한다. 나머지 학생은 대기 공간에서 응원 자세를 유지한다.

### P-37. 마지막 CourseSummary 단계 제거와 성공 팝업

결정값:

### P-38. 단계별 입력 잠금과 월드 목표 안내

- 7단계 교수 컴퓨터에는 교수가 작업하지 않을 때만 공용 목표 마커를 표시한다. 작업 시작 시 숨기고, 완료 전 작업이 중단되면 다시 표시한다.
- 필수 대상은 Inspector의 명시적 참조와 facade binding으로만 제공한다. 이름 검색, 씬 전체 검색과 상태 polling은 사용하지 않는다.

### P-39. 미니웨이브 독립 준비 단계

결정값:

- `TutorialMiniWavePreparationStep`을 `ProfessorWork`와 `MiniWave` 사이의 독립된 `TutorialStepBase` 단계로 추가한다. 내부 substate나 별도 팝업으로 대체하지 않는다.
- 기존 enum 직렬화 값을 보존하기 위해 `MiniWavePreparation` ID는 새 값으로 추가하고, Director의 실행 순서에서만 `MiniWave` 앞에 배치한다.
- 준비 단계에서는 정규 `StageRuntimeConfig.UsePreparation`을 사용하지 않는다. 튜토리얼 정책으로 타이머·혼잡도·프로젝트·탈출 판정을 정지하고 `Time.timeScale`은 1로 유지한다.
- 준비 단계 진입 시 P-28 고정 로드아웃과 미니웨이브 초기 수치를 적용하고, 학생 로스터를 한 번 선택하되 학생을 Warp하거나 Behaviour Tree를 시작하지 않는다. 전체 학생은 안정된 `Standby` 상태를 유지한다.
- 플레이어는 준비 단계에서 이동, 장비 교체, 보충 시설과 탈출구 정비를 사용할 수 있다. Tab을 누르면 현재 상호작용을 중단하고 준비 완료 상태를 체크포인트로 캡처한 뒤 단계를 완료한다.
- 준비 완료부터 `MiniWave` 진입까지의 패널 전환 동안 게임플레이 입력을 임시 차단한다. `MiniWave` 진입 시 선택된 로스터를 연수 출발 지점으로 Warp한 직후 행동을 시작하고 입력을 복원한다.
- 실패 후 `8단계 다시 시작`은 준비 Step을 다시 실행하지 않는다. 준비 완료 시점의 체크포인트와 동일 로스터를 복원한 뒤 미니웨이브를 즉시 다시 시작한다.
- 기존 문서의 “최초 8단계 진입 상태”는 이 결정 이후 “미니웨이브 준비 완료 Tab 입력 시점”을 의미한다.

### P-40. 3단계 위험 행동의 월드 부가효과 차단

결정값:

- 이 억제는 `TutorialRiskResponseStep`이 발행한 위험 scripted request에만 적용한다. 정상 scripted 행동, 정규 스테이지와 미니웨이브의 동일 행동은 기존 결과를 유지한다.

### P-41. 6단계 학생 부스터 광분 효과 차단

결정값:

- 차단은 6단계가 활성인 동안 해당 작업 대상 학생에게만 적용하고, 단계 종료 시 기존 광분 이벤트를 복원한다. 정규 스테이지, 다른 튜토리얼 단계와 미니웨이브의 부스터 효과는 변경하지 않는다.

### P-42. 미니웨이브 준비 완료 전환의 입력 잠금 제거

결정값:

### P-43. StepInfoPanel 콘텐츠의 접기·펼치기 가시성

결정값:

- `StepInfoPanel`의 배경과 높이 Tween 대상은 활성 상태로 유지하고, 텍스트·구분선·아이콘·이미지 등 단계 콘텐츠는 별도 `StepInfoContentRoot` 아래에 둔다.
- 패널 접기 시작 시 `StepInfoContentRoot`를 비활성화하고, 다음 단계 정보를 적용한 뒤 패널 펼치기가 완전히 끝난 시점에 다시 활성화한다.
- 0단계 최초 진입도 최소 높이 상태를 한 프레임 표시한 뒤 이후 단계와 동일한 펼치기 효과를 재생한다.
- 개별 TMP 또는 Graphic 배열을 관리하지 않는다. 앞으로 추가하는 단계 UI도 같은 동작이 필요하면 `StepInfoContentRoot`의 자식으로 배치한다.
- 최소 높이에서도 유지할 UI는 콘텐츠 루트 밖에서 `StepInfoPanel`의 직접 자식으로 둔다.

### P-44. 3단계 위험 행동 포커스 말풍선

결정값:

- 3단계 위험 학생이 행동 지점에 도착해 실제 scripted 행동을 시작한 뒤 플레이어 포커스 대상이 되면 해당 행동의 추가 정보를 말풍선으로 표시한다.
- 말풍선 위치는 각 학생 Humanoid Animator의 `HumanBodyBones.UpperChest` 본을 우선 추적한다. Avatar에 선택 본인 UpperChest가 매핑되지 않은 경우 `HumanBodyBones.Chest`를 호환 fallback으로 사용한다. 본 회전과 무관한 월드 Y축 높이 오프셋을 더해 머리 부근에 표시하며, Inspector 기본 오프셋은 `0.6m`이고 `0.5~0.7m` 범위에서 조정한다.
- 쓰러진 위험 학생도 3단계가 진행 중이고 포커스 대상이면 말풍선을 표시하며 래그돌과 함께 움직이는 UpperChest 본을 계속 추적한다.
- 포커스를 벗어나면 말풍선만 일시적으로 숨기고, 쓰러진 학생을 다시 포커스하면 다시 표시한다. 체력 0 판정은 말풍선 표시 자격을 제거하지 않는다.
- 4명의 위험 학생을 모두 저지해 `4/4`가 된 직후 말풍선 기능을 완전히 비활성화한다. 단계 강제 종료와 씬 종료에서는 `OnExit` 정리 경로에서도 비활성화하고 이벤트를 해제한다.
- 위험 행동별 제목과 설명은 `TutorialCourseDefinition`에서 사용자가 작성한다. 코드가 문서에 없는 설명 문구를 임의로 생성하지 않는다.
- 말풍선은 별도 거리, 감지 반경, 학생 LayerMask 또는 차단 LayerMask 판정을 만들지 않는다. 정규 `StudentDetector`가 `StudentInfo`에 반영한 현재 포커스 학생 상태와 변경 이벤트를 그대로 관찰한다.
- `TutorialStudentFocusSource`는 자체 물리 감지를 수행하지 않고 기존 `StudentInfo` 참조 하나만 보유하는 튜토리얼 연결부로 사용한다.

### P-45. 3-2 정전 복구 연수

결정값:

- `RiskResponse` 다음과 `InnocentStudent` 사이에 독립된 `PowerRecovery` Step을 추가하고 화면에는 `3-2`로 표시한다.
- 단계 진입 시 메인 스테이지와 동일하게 `StageController.Hacked()`를 호출해 해킹 정전 팝업과 hack `SoundData`를 함께 재생하고, 이어서 `LabLightSystem.TurnOff()`를 호출해 연구실 조명 그룹, reflection과 ambient light를 정전 상태로 전환한다.
- 정전 이후의 전기박스 활성화, 경고등·파티클, F 길게 누르기 복구, 패시브 복구 속도와 조명 복구는 기존 `FuseBox`, `ClickAndWait`, `LabLightSystem` 흐름을 그대로 사용한다.
- 메인 스테이지의 기존 `FuseBoxMarkerUI` 반응은 그대로 유지한다. 이와 별도로 튜토리얼 공용 `TutorialObjectiveMarkerPresenter`의 월드 대상 화살표를 Inspector에서 지정한 전기박스 `MarkerAnchor`에 표시하고 복구 즉시 제거한다. 별도 전기박스 전용 마커 prefab은 추가하지 않는다.
- `LabLightSystem.LightsOnEvent`가 실제 조명 복구 뒤 발생한 시점에 목표를 `1/1`로 만들고 단계를 한 번만 완료한다. 상태 polling은 사용하지 않는다.
- 별도 제한 시간, 실패, 자동 복구와 단계 재시작을 추가하지 않는다. 학생을 새로 선발하지 않으며 3단계 학생의 자동 기상·배경 복귀를 그대로 진행한다.
- 3단계 scripted 해킹의 조명 OFF 억제는 유지한다. 3-2의 정전은 해킹 결과가 아니라 Step이 시작한 별도의 확정 연출이다.

### P-46. 3-3 전자레인지 관리 연수

결정값:

- `PowerRecovery` 다음과 `InnocentStudent` 사이에 독립된 `MicrowaveManagement` Step을 추가하고 화면에는 `3-3`으로 표시한다.
- 음식 목록은 별도 튜토리얼 배열을 만들지 않고 StudentDB index 0 학생 프리팹의 기존 `PlateAttacher._fireCauseFoods`와 `_fireNonCauseFoods`를 읽기 전용 스냅샷으로 사용한다.
- 위 기존 음식 총수만큼 학생을 선택해 각자 서로 다른 음식 하나를 고정 지급한다. 학생들은 기존 연수 시연과 같이 연수 출발 지점으로 Warp한 뒤 음식 시연 슬롯까지 달려가 일렬로 선다. 이동 중에는 `TrainingTransit`, 도착 후에는 `Standby`와 같은 보호 규칙을 사용해 AI·공격·피해·부스터·탈출·작업·혼잡도 원인과 스테이지 집계에서 제외한다.
- `Carrying` 애니메이션 이벤트가 기존 랜덤 `LiftPlate()`를 호출하더라도 3-3 동안은 학생별 지정 음식만 다시 표시하며 다른 음식으로 교체하지 않는다.
- 기본 설정에서는 서로 다른 전자레인지 두 개 중 정상/위험 역할을 매 진입 시 무작위로 정한다. Inspector에서 고정 위험 전자레인지 사용을 켜고 facade에 등록된 두 대 중 하나를 연결하면 해당 전자레인지에 항상 위험 음식을 배정한다. 기존 정상 음식 목록 하나와 위험 음식 목록 하나는 두 방식 모두 각각 무작위로 선택한다.
- 두 전자레인지에 각각 고정 `MarkerAnchor`를 명시적으로 연결하고, 이번 진입에서 위험 음식이 배정된 전자레인지 하나에만 튜토리얼 공용 월드 화살표 마커를 표시한다. 위험 음식을 꺼내거나 단계가 종료되면 즉시 제거한다.
- 연수 중 두 전자레인지는 음식 제거 전까지 기존 작동음과 조리 연출을 유지한다. 위험 음식은 기존 위험 조리 VFX를 재생하지만 폭발, 화재, 폭발음과 흔들림은 발생시키지 않는다.
- 정상 음식을 꺼내면 기존 `NormalFoodRemoved` 혼잡도 원인과 경고는 적용하지만 목표는 완료하지 않는다. 위험 음식을 실제로 꺼낸 `FoodRemovedEvent`만 `(1/1)` 완료로 인정한다.
- 별도 제한 시간, 실패, 자동 재시작과 상태 polling을 추가하지 않는다. 완료 또는 단계 종료 시 남은 전자레인지의 작동음·VFX·음식을 정리하고 폭발 억제를 해제하며, 음식 학생의 소품을 제거한 뒤 배경 복귀시킨다.
- 폭발 억제의 기본값은 꺼짐이다. `MicrowaveManagement`가 명시적으로 활성화한 튜토리얼 runtime에만 적용하며 정규 스테이지와 미니웨이브의 전자레인지 조리·폭발 흐름은 변경하지 않는다.

### P-47. 3-1 정상 학생 저지 혼잡도

결정값:

- `RiskResponse`를 화면 단계 기준 `3-1`로 취급한다.
- 3-1에서 플레이어가 정상 행동 학생을 체력 0으로 만들면 정규 스테이지와 같은 `InnocentDown` 혼잡도 증가와 경고를 발생시킨다.
- 정상 학생 Down은 위험 행동 저지 진행도에 포함하지 않고 현재 문제를 초기화하거나 감소시키지 않는다.
- 총기 발사, 저질 노래, 흡연과 위험 행동 자체의 혼잡도 등 다른 증가 원인은 기존처럼 차단한다.

### P-48. 전자레인지 작동 중 음식 회전

결정값:

- 튜토리얼 전용 연출이 아니라 `Microwave` 자체 기능으로 구현한다.
- 전자레인지가 작동 중이고 음식이 들어 있을 때 음식 오브젝트를 월드 Y축 기준 시계방향으로 계속 회전시킨다.
- 정규 스테이지 조리와 3-3의 폭발 억제 조리 양쪽에 동일하게 적용한다. 정지·음식 제거·폭발 후에는 회전하지 않는다.
- 회전 속도는 전자레인지별 serialized 값으로 조절하며 기본값은 초당 90도다.

## I. 기술 설계 승인 항목

아래는 게임 규칙이 아니라 코드 구조 선택이다. 승인 전에는 확정 구현안으로 간주하지 않는다.

### T-01. 전용 튜토리얼 씬 사용

제안 내용: 정규 `SStage1`에 튜토리얼 분기를 넣지 않고 `TutorialStage` 씬을 별도로 둔다.

결정값: 승인. 별도 튜토리얼 씬을 사용한다. 씬 생성과 구성은 사용자가 Unity Editor에서 직접 진행한다.

### T-02. `TutorialDirector` 단계 상태 머신

제안 내용: 하나의 Director가 단계 진입, 달성, 종료와 재시작을 소유한다.

결정값: 승인. 하나의 `TutorialDirector`가 단계 진입, 달성, 종료와 재시작을 소유한다.

### T-03. 기존 시스템 이벤트/API 추가

제안 내용: 튜토리얼이 private 상태나 Blackboard를 직접 바꾸지 않고, `StageController`, `PostStudent`, `ExitGate` 등에 공개 이벤트와 제한된 제어 API를 추가한다.

결정값: 승인. 기존 시스템에 공개 이벤트와 제한된 제어 API를 추가한다.

### T-04. 레시피형 체크포인트

제안 내용: Behaviour Tree 내부 상태를 저장하지 않고, 단계 재시작 시 학생을 재스폰하고 월드를 기준 상태로 다시 구성한다.

결정값: 승인. Behaviour Tree 런타임 상태를 저장하지 않고 단계 기준 상태를 다시 구성한다. 다만 이후 확정된 `P-36`과 `T-06`에 따라 튜토리얼 씬 시작 시 생성한 DB 전체 학생 풀은 8단계 재시작 때 파괴하거나 재스폰하지 않는다. 같은 학생 풀의 체력, 위치, 모드와 행동 런타임을 최초 8단계 진입 기준으로 동기적으로 재구성한다. 최초 제안의 “학생 재스폰” 문구보다 이 결정이 우선한다.

### T-05. 정규 진행 데이터 분리

제안 내용: 튜토리얼용 런타임 설정과 장비를 사용해 `WaveSystem`, `InventorySystem`의 정규 진행 상태를 직접 변경하지 않는다.

결정값: 승인. 튜토리얼 런타임 상태를 정규 `WaveSystem`과 `InventorySystem` 진행 데이터에서 분리한다.

### T-06. 튜토리얼 학생 행동 런타임 초기화

결정값:

- 메인 스테이지의 `StageStartEvent -> 기상 애니메이션 -> StartBehavior()` 흐름은 변경하지 않는다.
- 튜토리얼 씬 시작 시 `P-36`에 따라 DB 전체 학생 풀을 생성한 뒤, `TutorialActorDirector`가 튜토리얼 전용 명시적 초기화 API를 학생마다 한 번 호출한다.
- 명시적 초기화는 학생의 필수 컴포넌트와 참조를 연결하고 `Blackboard`와 루트 Behaviour Tree를 구성한다. 전체 학생의 초기화 호출이 동기적으로 끝난 뒤에만 0단계에 진입한다.
- 초기화된 행동 런타임은 `Loyalty`, `Standby`, `TrainingTransit`, `ReturnTransit`, `Cheer` 모드에서 평가하지 않는다. `Training`의 지정 행동 또는 `MiniWave` 행동이 시작될 때만 해당 모드에 맞게 평가한다.
- 3단계, 4-1, 6단계와 8단계에서 학생을 선발할 때 별도의 Ready 이벤트, 상태 polling 또는 준비 대기를 사용하지 않는다.
- 8단계 재시작은 학생을 재스폰하거나 Ready를 다시 기다리지 않는다. `T-04`에 따라 기존 학생 풀의 의미 상태와 행동 런타임을 최초 8단계 진입 기준으로 동기적으로 재구성한다.
- Ready 제한 시간, 준비 실패 재스폰, 자동 복구와 자동 단계 재시작은 구현하지 않는다.
